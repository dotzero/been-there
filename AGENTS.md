# Repository Guidelines

## Snapshot

Been There is a Vite + React SPA for rendering, sharing, and exporting a visited-countries Mapbox map. There is no backend; app state lives in the URL.

## Files

- `src/main.jsx`: React entrypoint only.
- `src/App.jsx`: main React app state, effects, event handlers, and JSX.
- `src/config.js`: app defaults, supported languages/map modes, and Mapbox token resolution.
- `src/i18n.js`: locale registration, interface messages, and country display names.
- `src/urlState.js`: URL parsing, compact visited-country encoding, and URL writes.
- `src/mapboxMap.js`: Mapbox setup, camera behavior, projections, visited layers, and availability checks.
- `src/mapExport.js`: PNG export and logo drawing.
- `src/countries.js`: country metadata, ISO code lists, tiny-country marker data.
- `src/styles.css`: all styling and responsive layout.
- `public/`: static assets copied by Vite.
- `etc/nginx.conf`, `etc/docker-entrypoint.d/`: production nginx and runtime token injection.
- `dist/`: generated by `npm run build`; never edit manually.

## Module Boundaries

- Keep React rendering and user workflows in `src/App.jsx`; avoid moving Mapbox implementation details or URL codecs into components.
- Keep URL compatibility logic in `src/urlState.js`. Preserve legacy `c=` decoding and compact `v=` encoding unless intentionally migrating share URLs.
- Keep Mapbox-only code in `src/mapboxMap.js`, including the `mapbox-gl` import, Mapbox CSS import, layers, projections, viewport zoom, and availability checks.
- Keep export-only canvas work in `src/mapExport.js`; do not mix download/canvas code into Mapbox layer helpers.
- Keep language text in `src/i18n.js`; when adding UI strings, update both English and Russian messages.
- Keep runtime configuration in `src/config.js`; do not read `import.meta.env` or `window.__RUNTIME_CONFIG__` from feature modules.

## Commands

- `npm install` installs dependencies.
- `npm run dev` starts Vite on `0.0.0.0`; open `http://localhost:5173/`.
- `npm run lint` runs ESLint.
- `npm run build` creates `dist/`.
- `npm run preview` serves the built app.
- `MAPBOX_TOKEN=pk... docker compose up` runs the nginx container with a runtime Mapbox token.

## Code Rules

- Use ES modules, React function components, two-space indentation, semicolons, single quotes, and `const` unless reassignment is needed.
- Naming: constants `SCREAMING_SNAKE_CASE`, components `PascalCase`, other functions/variables `camelCase`.
- Keep URL state backward compatible unless deliberately migrating it. Current state covers visited countries, language, style, and projection.
- Preserve Mapbox token behavior: local builds read `import.meta.env.MAPBOX_TOKEN`; Docker injects `window.__RUNTIME_CONFIG__.MAPBOX_TOKEN` into `index.html`.
- Do not commit real `.env` values. Browser Mapbox tokens are public, but production tokens should be URL-restricted.
- Keep behavior modules scoped; URL compatibility belongs in `src/urlState.js`, map behavior in `src/mapboxMap.js`, and UI workflow in `src/App.jsx`.
- Prefer extracting cohesive helpers over splitting tiny JSX fragments; only create components when it reduces real workflow complexity.

## Verification

No automated tests exist. For code changes, run:

```bash
npm run lint
npm run build
```

For UI or behavior changes, manually verify country selection, tiny-country markers, share URLs, back/forward, language, day/night style, flat/globe projection, PNG export, mobile viewport behavior, and missing-token/WebGL error states. Pay special attention to iOS Safari viewport height when changing map sizing or zoom.

## Commits and PRs

Use short imperative commit subjects, e.g. `Fix fallback map` or `Pass MAPBOX_TOKEN via runtime`.

PRs should include a summary, verification commands, screenshots or recordings for visual changes, linked issues when relevant, and explicit notes for `MAPBOX_TOKEN`, Docker, nginx, URL serialization, or Mapbox behavior changes.
