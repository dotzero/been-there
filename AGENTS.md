# Repository Guidelines

## Snapshot

Been There is a Vite + React SPA for rendering, sharing, and exporting a visited-countries Mapbox map. There is no backend; app state lives in the URL.

## Files

- `src/main.jsx`: React app, Mapbox setup, layers, camera behavior, URL state, switches, PNG export.
- `src/countries.js`: country metadata, ISO code lists, tiny-country marker data.
- `src/styles.css`: all styling and responsive layout.
- `public/`: static assets copied by Vite.
- `etc/nginx.conf`, `etc/docker-entrypoint.d/`: production nginx and runtime token injection.
- `dist/`: generated by `npm run build`; never edit manually.

## Commands

- `npm install` installs dependencies.
- `npm run dev` starts Vite on `0.0.0.0`; open `http://localhost:5173/`.
- `npm run lint` runs ESLint.
- `npm run build` creates `dist/`.
- `npm run preview` serves the built app.
- `MAPBOX_TOKEN=pk... docker compose up` runs the nginx container with a runtime Mapbox token.

## Code Rules

- Use ES modules, React function components, two-space indentation, semicolons, single quotes, and `const` unless reassignment is needed.
- Naming: constants `SCREAMING_SNAKE_CASE`, components `PascalCase`, other functions/variables `camelCase`.
- Keep URL state backward compatible unless deliberately migrating it. Current state covers visited countries, language, style, and projection.
- Preserve Mapbox token behavior: local builds read `import.meta.env.MAPBOX_TOKEN`; Docker injects `window.__RUNTIME_CONFIG__.MAPBOX_TOKEN` into `index.html`.
- Do not commit real `.env` values. Browser Mapbox tokens are public, but production tokens should be URL-restricted.
- Keep `src/main.jsx` changes scoped; it owns most app behavior.

## Verification

No automated tests exist. For code changes, run:

```bash
npm run lint
npm run build
```

For UI changes, manually verify country selection, tiny-country markers, share URLs, back/forward, language, day/night style, flat/globe projection, PNG export, mobile viewport behavior, and missing-token/WebGL error states.

## Commits and PRs

Use short imperative commit subjects, e.g. `Fix fallback map` or `Pass MAPBOX_TOKEN via runtime`.

PRs should include a summary, verification commands, screenshots or recordings for visual changes, linked issues when relevant, and explicit notes for `MAPBOX_TOKEN`, Docker, nginx, URL serialization, or Mapbox behavior changes.
